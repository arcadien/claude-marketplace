# Plugin Marketplace — Design Spec

**Date:** 2026-06-10  
**Status:** Approved

## Overview

A personal Claude Code plugin marketplace: a monorepo containing plugins, an auto-generated JSON registry, and a static Astro site deployed to GitHub Pages.

## Architecture

```
marketplace/
├── plugins/
│   └── <plugin-name>/
│       ├── plugin.json       ← standard Claude Code format
│       └── skills/, hooks/,  ← plugin assets
├── scripts/
│   └── build-registry.ts     ← aggregates plugins/*/plugin.json → registry.json
├── registry.json             ← build artifact (not committed, generated by CI)
├── site/                     ← Astro application
│   ├── src/
│   │   ├── pages/
│   │   │   ├── index.astro         ← plugin listing
│   │   │   └── plugins/[name].astro ← detail page
│   │   └── layouts/
│   └── astro.config.mjs
└── .github/
    └── workflows/
        └── build.yml         ← build + deploy to GitHub Pages
```

## Data Format

### plugin.json (per plugin)

Standard Claude Code format, minimum required fields:

```json
{
  "name": "plugin-name",
  "version": "1.0.0",
  "description": "What the plugin does",
  "author": "Aurelien",
  "skills": [],
  "hooks": [],
  "commands": []
}
```

### registry.json (generated)

```json
{
  "version": 1,
  "generatedAt": "2026-06-10T00:00:00Z",
  "plugins": [
    {
      "name": "plugin-name",
      "version": "1.0.0",
      "description": "...",
      "author": "Aurelien",
      "installPath": "plugins/plugin-name"
    }
  ]
}
```

## Astro Site

### Pages

- **`/`** — lists all plugins: name, description, version, link to detail page
- **`/plugins/[name]`** — detail page: full description, skills/hooks/commands, installation instructions

### Style

Minimal, no external CSS framework. Astro native.

### Installation instructions (shown on each detail page)

```bash
claude plugin install https://arcadien.github.io/marketplace/registry.json <plugin-name>
```

Public registry URL: `https://arcadien.github.io/marketplace/registry.json`

> Note: exact CLI syntax to be confirmed at implementation time.

## build-registry.ts Script

1. Glob `plugins/*/plugin.json`
2. Parse each file
3. Generate `registry.json` at repo root
4. Write generation timestamp

Run via `npm run build:registry` (or `ts-node` / `tsx`).

## CI/CD

### `.github/workflows/build.yml`

Triggered on push to `main`:

1. `npm run build:registry` — generates `registry.json`
2. `npm run build` (Astro) — generates static site
3. Deploy to GitHub Pages via `actions/deploy-pages`

No cron needed: every change goes through a commit.

## Adding a Plugin

1. Create `plugins/<name>/plugin.json` + assets
2. Commit + push to `main`
3. GitHub Action regenerates `registry.json` + rebuilds the site automatically

## Out of Scope

- Authentication
- Rating/comment system
- Scraping external repos
- Multi-author support
